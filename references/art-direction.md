# 从方法到画法

新方法图、明显不满意的整体改版，以及新的组件类别需要读本指南。移动一个标签不需要重新设计。产物不是一份更长的需求表，而是一套**能进入实际绘图的选择**：主线、表现方式、空间分配、参考职责、视觉规则和本轮要验证的问题。

## 1. 先找读者要看懂的变化

从正文、公式和必要的实现中写一句“什么输入，经什么关键变化，得到什么输出”。再问：去掉哪个变化，这张图就无法解释论文的贡献？那个变化应得到最多空间。

把科学结构与版面分开：节点是方法中的对象或操作；面板只是同一组节点的展示位置。一个模块的总览与放大图不是执行两次，左右相邻也不意味着数据相连。

对每个拟画元素做选择：

| 内容 | 通常采用的表达 | 不应采用的替代 |
|---|---|---|
| 已知背景模块、非贡献的编码器 | 一个可辨识的紧凑模块 | 为了填空展开完整网络 |
| 创新操作及其前后变化 | 展开局部关系或对照同一实例 | 两个名称方框，中间一根箭头 |
| 历史、当前观测、临时结果 | 空间分层、时间索引、不同容器 | 一律画成“Memory” |
| 多对象共享关系 | 有行列含义的矩阵、二部关系 | 没有索引的彩色马赛克 |
| 训练专用监督 | 独立且明确标记的训练分支，或留给正文 | 混入推理输入 |

每个关键节点和连接都应能指向科学来源。来源只写“论文”不够：记录对应小节、公式标签或实现位置。来源没有给定内部运算时，可以画经过确认的抽象接口，不能凭常识选择一个具体 GRU、ODE 或 attention 变体。

标签优先是对象、操作、结果；解释句移到题注。先减少信息层级和重复表达，再缩字号。最终尺寸下必须同时辨认模块名、索引、关键运算符。不要用“字少”省掉改变机制理解的 null、共享权重或时间边界。

## 2. 参考不是一张笼统的“风格图”

实际看图后，为每张入选参考写三件事：**借什么、不借什么、用在哪**。

- 主参考决定视觉语法：密度、字体性格、线条与色块的关系。
- 辅助参考只承担明确职责，例如局部放大、开放网格、图例组织或概率编码。
- 科学来源决定箭头拓扑与符号含义。参考图即使画了相同符号，也不自动有相同含义。
- 参考冲突时明确选择，不把 Comic 字体、Roman 边界和第三张图的粗箭头无区别拼在一起。

检索时同时描述**科学概念与可见结构**，例如 `flow matching curved grid vector field figure`，而不只搜 `beautiful flow diagram`。用户要近期论文时按日期筛选，直接打开原论文图，记录论文时间、图号、借用部位与对应本地图片；摘要文本不是已看过图的证据。图库已足够匹配时无需重复检索。

两条素材路径应分清：图片先验影响生图的空间和风格；可编辑组件提供可复用的对象结构。一个来源不明的位图不是原生组件。二维分布、开放三维网格、一般框图分别是不同表达类别，不能把某一图的桃绿配色或网格偏好升级为所有论文的默认外观。

## 3. 选构图，不做一排换色变体

整体设计不确定时，提出少量真正不同的构图，并比较读图代价。例如：

- **总览＋局部展开**：主线短，细节有明确归属；代价是需要读者在两种尺度间对应。
- **直接展开的流程带**：每次计算只出现一次；代价是分支多时会变宽，历史回路容易绕远。
- **前后状态对照**：最擅长解释一个机制改变了什么；代价是完整系统接口通常要另放小总览。

推荐理由必须针对论文，不是“第一种更专业”。选择一个方案进入一次生图输入，不把多个替代版面混进同一提示。已经确认的构图不因一次局部批注重选。

按解释负担分配面积，不默认三栏等宽。先用逻辑组的中心、底线和组间距组织对象，再考虑外框。主要路径尽量连续；独立细节不应靠长折线硬塞回主线。

## 4. 连线是一种语义

| 关系 | 画法与端点 | 需要排除的误读 |
|---|---|---|
| 数据传递 | 有向箭头，接到实际模块边界或操作 | 相邻即相连；断在边框前 |
| 条件影响 | 与主线可区分，标明条件对象 | 当作另一份主输入或状态写入 |
| 跨时间反馈 | 单独返回通道，给出时间索引 | 一帧内反复提交、无限循环 |
| 局部放大 | 源区域两角到展开区域的两根无箭头引线 | 一个模块被误认为多执行一次 |
| 同一对象对应 | 索引、同色或轻连接 | 没有依据的数据流 |

相同来源进入同一区域时可用共同主干，分叉必须明确。只是交叉的线不要带汇合点；真正汇合不能留缝。区分“删掉箭头尖”和“删掉科学连接”，前者不能无意改变后者。

## 5. 矩阵、局部概率与图例

全局行列关系本身重要时保留完整矩阵，并说明行、列、颜色强度及 null 的含义。若下一个面板只解释其中一处变化，提取相关行/列或概率格，不再重复同一整矩阵；用来源索引保留可追溯性。

概率格可以用相同边长，条长由类别数决定；不要拉伸每格去填满容器。离散类别色与连续概率强度不是一回事。保持类别映射稳定，并标明灰色到底是低概率、无效边还是 null，不能一色多义。

图例保留“不解释就会误解”的项：类别色、关键缩写、特殊运算。普通边框与显然的数据箭头通常不值得占一整行。图内标签、局部注释、图例三者不要重复说同一句话。虚线边框可以把一个必要图例收成整体，但不能用大框掩盖只有两项内容。

`⊙`、`×`、`+` 按论文公式选择。图标库解决轮廓质量，不解决数学含义；参考中的矩阵乘符号不可直接借作逐元素乘。简单数学符号可以用一致数学字形或干净矢量，不强制依赖图标库。

## 6. 一套风格要协调，而不是只换字体

| 决定 | Comic | Roman | Modern |
|---|---|---|---|
| 标签与数学 | 轻松标签字体＋稳定数学字形 | 衬线标签与协调数学字形 | 清楚的无衬线标签＋数学字体 |
| 轮廓 | 适度圆角，不用装饰性抖动破坏连接 | 克制边框，减少圆润卡片感 | 简洁几何、统一圆角体系 |
| 线与留白 | 有节奏但不粗重 | 细线、层级分明 | 明确对齐与组距 |

为当前图分别决定文字色、主连接线、模块边界、背景层、科学类别色。大背景不占用科学类别含义；主体颜色以局部填色配深文字为起点，不必全图饱和或全图浅色。实际缩小看，而不是只看放大后的颜色值。

用户说“颜色不对”时，核对是类别错位、层级太弱、背景抢色还是风格偏离。已确认的类别色先保护；修改背景不顺带改概率格。字体也按角色查，避免某个标签或运算符落成孤立字体。

## 7. 把反馈变成可检验的设计假设

| 反馈 | 先区分 | 有针对性的修改 |
|---|---|---|
| 太空 | 必要隔离 / 容器过大 / 关键机制缺失 | 保留 / 收紧 / 补有来源的内部关系 |
| 太乱 | 阅读顺序混乱 / 连线过密 / 重复表达 | 换主次 / 合理主干或独立细节 / 提取局部 |
| 太简陋 | 只画名称，没有呈现关键变化 | 用一个有来源的实例展开变化，不加装饰 |
| 很违和 | 字体、符号、线宽、底色中哪一项偏离参考 | 只调整相关维度，并检查原本的语义色 |
| 恢复之前的图例，只改这里 | 用户撤销了哪个具体决定 | 恢复那个决定，保持其他已认可范围 |

记录一句“问题假设 → 本轮修改 → 如何判定解决”。不要同时重排版、换所有颜色、改全部符号，使用户无法判断哪项有效。反馈确实指向整类表达错误时，允许改构图类别，而不在原错误上反复美化。

## 8. 候选图到可编辑图的交接

生成图可帮助确定密度、构图和视觉语法，但不能自动成为科学正确的答案。按照方法图结构逐项核对候选；若候选新增箭头、丢失 null 或写错公式，重建时以科学来源为准。变化较大时给出新预览，不能以“复刻”为名静默改掉已认可布局。

给逻辑组、运算、标签和连接命名；保存源到 PPT 对象的对应关系。照片和连续纹理可作为位图资产，方法框图、文字、概率格、运算及连接按可编辑要求重建。不要承诺任意手工改 PPT 都能自动回写源文件。

最终检查分开回答：

1. **读懂了吗？** 不看题注能找到输入、关键变化和输出；放大关系不会读成额外运算。
2. **科学正确吗？** 时间、共享权重、运算和分支有来源，示意值不被当作测量。
3. **视觉成立吗？** 在最终使用尺寸检查字号、空白、连接、色彩和图例，不只在编辑画布看。
4. **真能编辑吗？** 检查实际导出的 PPT，并试改代表对象；局部修改后检查保护区域。

其中任何一项通过都不能替代其他项。当前设计方案可用 `afw.py priors --design ... --layout ...` 进入生图提示；结构校验不代替这些判断。格式见 [design-plan.md](design-plan.md)。
